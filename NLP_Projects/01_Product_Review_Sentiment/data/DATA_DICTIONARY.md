# Data dictionary — product_reviews.csv

Synthetic product reviews for a fictional e-commerce shop ("ShopKart"), generated by `generate_data.py` (seed 42).
4,000 reviews plus 60 duplicated rows added on purpose = 4,060 rows. Licence: created for this course; free to use and share.
No real customer wrote any of these reviews.

| Column | Type | Description | Values / range | Missing |
|---|---|---|---|---|
| `review_id` | text | Review identifier. Not a feature. | R00001–R04000 | none |
| `product_category` | category | Category of the reviewed product | electronics, clothing, home, beauty, grocery | none |
| `review_text` | free text | What the customer wrote. **The only model input.** Contains emojis, typos, Hinglish words, ALL CAPS / all lower case | 1–27 words | 22 missing + 13 only spaces |
| `rating` | integer | Star rating the customer clicked | 1–5 | none |
| `verified_purchase` | boolean | Reviewer bought the product on ShopKart | True (about 80%), False | none |
| `review_date` | date (text) | Date the review was posted | 2024-01-01 to 2025-12-30 | none |
| **`sentiment`** | category | **Target.** Overall opinion as tagged by a human annotator | positive (~49%), negative (~29%), neutral (~22%) | none |

Counts above include the duplicated rows. After removing duplicates and empty reviews the notebook keeps 3,965 reviews.

## What the target means

- **positive** — the customer is happy overall and would recommend the product (may still mention a small issue).
- **neutral** — average, "okay", "does the job", or a genuinely mixed opinion with no clear winner.
- **negative** — the customer is unhappy: defects, wrong item, bad quality, regret, would not recommend.

## How the reviews were generated

For each review the generator picks a category, a product (e.g. *power bank*, *kurta*, *pressure cooker*, *sunscreen*,
*basmati rice*) and a true sentiment, then builds the text from phrase pools:

- **aspect phrases** per category ("the battery dies fast", "the colour faded after the first wash", "it tasted stale"),
- **general phrases** ("Value for money.", "Waste of money.", "Does the job."),
- **negations** ("Not bad at all.", "No complaints so far.", "Not worth it.", "Would not recommend."),
- **mixed reviews** joined with *but / however / although* ("Great screen but the battery dies fast"),
- **sarcasm** for a few negative reviews ("Wow, stopped working in two days. Amazing quality 🙄"),
- **Hinglish** ("Bahut accha product.", "Paisa vasool!", "Bekaar product.", "Theek hai."),
- **emojis**, **typos** (swapped or dropped letters), stretched words ("gooood") and random upper/lower case.

The **rating** is drawn from a distribution that *usually* matches the sentiment (positive → mostly 4–5 stars, neutral →
mostly 3, negative → mostly 1–2) but not always, as with real customers.

## Deliberate data quality problems

| Problem | How many | How the notebook handles it |
|---|---|---|
| Duplicate rows | 60 | dropped before splitting |
| Empty reviews (missing or only spaces) | 35 | dropped (no text to learn from); the API rejects empty text |
| Label noise (label changed to a wrong class) | about 6% of reviews | kept — it limits the best possible score; found again in the error analysis |
| Hard cases (mixed, sarcasm, lukewarm "not bad") | several hundred | kept — they are why the task is not 100% solvable |
